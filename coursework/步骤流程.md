# P2 自适应加权融合实现与实验流程

## 1. 目标与范围

本实验在仓库现有 Final 模型上，只调整 P2 检测分支的一处特征融合：把普通 `Concat` 替换为可学习的自适应加权拼接（Adaptive Weighted Concat，简称 P2-AWF）。模型仍保留 P2/P3/P4 检测输出、现有特征融合路径和 `C2fCBAMv2` 模块。

该实验检验的假设是：浅层细节、骨干 P2 特征和上采样语义特征对小目标检测的贡献不同，模型学习它们的相对权重后，可能改善 P2 分支表现。它是待验证假设，不保证指标提升。

不在本实验中增加新的注意力模块、检测头、数据增强或改变推理设置。推理阶段继续使用已经锁定的 P8 评估配置。

## 2. 融合位置和计算方式

Final 的 P2 融合节点接收三路同空间尺寸特征：

1. 主干第一层特征下采样到 P2 尺度后的浅层特征；
2. 主干网络已有的 P2 特征；
3. P3 特征上采样到 P2 尺度后的语义特征。

原结构是：

```text
三路 P2 特征 -> Concat -> C2fCBAMv2 -> P2 Detect
```

新结构是：

```text
三路 P2 特征 -> 每路乘一个可学习权重 -> Concat -> 原 C2fCBAMv2 -> P2 Detect
```

设三路输入为 `x_i`，可学习参数为 `a_i`：

```text
w_i = 3 * softmax(a)_i
y = Concat(w_1*x_1, w_2*x_2, w_3*x_3)
```

所有 `a_i` 初始化为 0，因此初始化时 `softmax(a)_i = 1/3`、`w_i = 1`。这样模块初始前向与普通拼接数值一致，之后权重由训练学习。输出通道数仍为三路输入通道数之和，因此后续 C2f 和检测头的输入形状不变；新增参数只有三个融合 logits。

这属于分支级权重，不是逐通道注意力，也不替代 CBAM。

## 3. 涉及文件

- `ultralytics/nn/modules/conv.py`：定义 `AdaptiveWeightedConcat`。
- `ultralytics/nn/modules/__init__.py`：导出新模块。
- `ultralytics/nn/tasks.py`：注册模块并让 YAML 解析器计算拼接后的通道数。
- `model_configs/yolov8-p2_woP5_sandwich_CBAM_p2awf.yaml`：从 Final 派生，仅替换 P2 融合节点。
- `coursework/train_coursework.py`：新增 `final-p2awf` 训练模型选项。
- `coursework/test_p2_adaptive_fusion.py`：检查初始化等价性、参数梯度和输入数量。

## 4. 环境和模型检查

在仓库根目录、已激活课程指定的 Python 环境后运行：

```powershell
python coursework/check_environment.py
python -m unittest coursework.test_p2_adaptive_fusion -v
```

环境检查会尝试构建 `model_configs/` 下的所有 YAML。应确认新增配置显示 `OK`，并且新增单元测试全部通过。若本机没有 PyTorch，单元测试会被跳过；这不代表模型已验证，需在课程 GPU 环境重新运行。

另外要确认 P2-AWF 的模块权重可以反向传播，日志没有形状不匹配或未注册模块错误。

## 5. 训练公平性

改进组和 Final 对照组必须使用同一训练数据、数据划分、图像尺寸、epoch 数、batch size、随机种子、预训练权重策略和训练增强。当前统一训练入口默认种子为 42、图像尺寸为 640；正式值以小组锁定的共同协议为准。

推荐先用相同协议进行短训筛选，确认训练和验证流程可运行；再按共同正式协议完成 Final 与 P2-AWF 对比。两个模型都从同一个 `yolov8n.pt` 预训练初始化，不要让一个从 Final 的 `best.pt` 继续训练、另一个从 YOLOv8n 开始训练，否则训练历史不同，结果不可直接归因于融合结构。

短训示例：

```powershell
python coursework/train_coursework.py `
  --model final-p2awf `
  --epochs 5 `
  --batch 8 `
  --imgsz 640 `
  --seed 42 `
  --device 0 `
  --pretrained
```

正式训练时，将 `--epochs`、`--batch`、`--imgsz`、`--seed` 和数据路径设为与 Final 对照完全相同。结果保存在 `runs/coursework/final-p2awf/`。

训练报告应保留：

- 完整命令和环境版本；
- `best.pt` 路径；
- 参数量和预训练权重迁移日志；
- 每 epoch 的训练/验证指标、总训练时间；
- 最终权重的哈希值，便于复现。

## 6. 评估与模型选择

1. 只用 val 选择实验方案，不在 test-dev 上调整融合结构或推理参数。
2. Final 和 P2-AWF 使用同一份权重初始化策略、同一个 val 划分及相同 P8 推理配置。
3. 至少报告 mAP50、mAP50-95、Precision、Recall、F1、各类别 AP、参数量和端到端推理时延。
4. 重点检查 pedestrian、people、bicycle、motor 等小目标/难类，同时检查 car 等主要类别是否明显退化。
5. 如果总体 mAP 基本持平但小目标 Recall 提升，应结合 Precision、误检数和时延判断是否有实际收益；不能只凭可视化样例宣称提升。
6. 配置和权重选择锁定后，才在 test-dev 做一次最终评估，并完整记录使用的权重与配置。

P8 推理配置包括切片与整图分支、边界感知结果合并、IoS 和小框过滤。比较时必须使用同一版推理代码、阈值和输入设置，不能把不同评估口径的历史数字直接作对照。

## 8. 完成标准

- 新 YAML 能由本仓库 Ultralytics 8.1.20 成功构建。
- 加权拼接初始化输出与普通 `Concat` 一致，三个权重都有有限梯度。
- 新模型能成功训练至少一个 epoch，且训练日志显示权重参数参与优化。
- 训练协议和 P8 评估协议与 Final 对照一致。
- 结果同时记录精度、类别表现、参数量和推理速度；结论如实报告，包括负向或无显著变化结果。
- 不提交 VisDrone 数据集、`runs/`、`.pt`、`.onnx` 或 TensorRT 权重。
